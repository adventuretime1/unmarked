# Unmarked Rewrite

Use Unmarked's rewrite engine. Orchestrate the request from Claude Code, Codex,
Pi, or another host agent, but do not silently use that host agent as the rewrite
model. Complete the user's requested rewrite through the configured backend when
it is available; do not substitute unrelated setup or analysis for the requested
output.

A rewrite may improve prose or make it read more naturally, but it remains
model-generated by the provider recorded in the Unmarked report. Provider
separation does not prove human authorship, absence of a watermark, or detector
evasion. Never describe a model as "non-watermarked" without independent evidence.

## Workflow

1. Establish the actual source provider. Ask when it matters and is not known.
   Use `human` or `unknown` only when accurate; never infer provenance from style.
2. Inspect first:

   ```bash
   unmark inspect INPUT --format json --report inspect.json
   ```

   If recognized Unicode or metadata is the only requested issue, use
   `unmark-clean` and avoid unnecessary paraphrasing.
3. Choose a rewrite provider different from the source provider:

   - Do not rewrite Anthropic or Claude source with an Anthropic model.
   - Do not rewrite OpenAI, ChatGPT, or Codex source with an OpenAI model.
   - Apply the same separation to Google, Gemini, and other known providers.

   Apply this rule to every fallback model as well as the primary model. Unmarked
   normalizes common aliases, derives providers from namespaced model slugs, and
   refuses known overlap before creating the adapter. Supply `--rewrite-provider`
   when a custom endpoint or model name is ambiguous.
4. Check the configured backend before sending the user's text anywhere:

   ```bash
   unmark config rewrite-check --source-provider SOURCE --format json
   ```

   This makes no model call and never prints a credential. It verifies the model,
   endpoint, remote opt-in, provider separation, fallback chain, key-variable name,
   and whether that variable is set. If it fails, do not rewrite with the host
   agent as a fallback. Explain the blocker and help configure the external backend.

   Store only non-secret routing in `.unmark.toml` or the user's Unmarked config:

   ```toml
   [rewrite]
   backend = "openai-compatible"
   endpoint = "https://openrouter.ai/api/v1"
   model = "google/gemini-3.7-flash"
   rewrite_provider = "google"
   allow_remote = true
   key_env = "OPENROUTER_API_KEY"
   ```

   Have the user set the value outside the agent conversation and outside Git,
   for example in their shell or secret manager:

   ```bash
   export OPENROUTER_API_KEY=...
   ```

   Never ask the user to paste the key into chat. Never place the value in a CLI
   argument, TOML file, report, log, committed env file, or response.
5. Start at low intensity and write to a new file:

   ```bash
   unmark edit INPUT --rewrite --backend ollama --model MODEL \
     --source-provider SOURCE --rewrite-provider PROVIDER --intensity low \
     --output OUTPUT --report rewrite.json
   ```

   For an OpenAI-compatible remote endpoint:

   ```bash
   unmark edit INPUT --rewrite --backend openai-compatible \
     --endpoint ENDPOINT --model MODEL --key-env KEY_ENV --allow-remote \
     --source-provider SOURCE --rewrite-provider PROVIDER --intensity low \
     --output OUTPUT --report rewrite.json
   ```

   Remote calls require the user's approval and `--allow-remote`. Never put the
   API key itself in a command, file, report, or response.
6. Review the output, protected spans, fidelity rejections, result state, and JSON
   report. Use `medium` or `high` only when the user accepts broader changes.
   Use recursive rewriting deliberately because repeated paraphrasing increases
   drift risk.
7. Return the output path and a concise report summary. Name the actual generation
   provider and model recorded by the run. Do not paste the full
   rewrite through a source-provider host agent; let the user read the output
   file directly.

Keep the source unchanged. Treat accepted output as a draft requiring review.
Do not describe detector reduction as verified unless a named detector was
actually measured, and never claim that an unknown watermark is absent.
